## Architecture

This is a **RAG (Retrieval-Augmented Generation) chatbot** for querying course materials. It uses ChromaDB for vector storage and DeepSeek for AI responses via LangChain, served as a single FastAPI process that also hosts the static frontend.

### Backend component graph

```
app.py (FastAPI routes + static file serving)
  └─ rag_system.py (RAGSystem — orchestrator)
       ├─ document_processor.py (DocumentProcessor — parses .txt course files, chunks text)
       ├─ vector_store.py (VectorStore — ChromaDB with two collections)
       ├─ ai_generator.py (AIGenerator — DeepSeek API via LangChain with tool-use loop)
       ├─ session_manager.py (SessionManager — in-memory conversation history)
       └─ search_tools.py (ToolManager + CourseSearchTool — OpenAI function-calling abstraction)
```

`models.py` defines the shared data types: `Course`, `Lesson`, `CourseChunk` (Pydantic models). `config.py` holds all settings as a frozen dataclass, loaded from env vars via `python-dotenv`.

### How a query flows

1. `POST /api/query` hits `app.py` → `RAGSystem.query()`
2. `RAGSystem` builds a prompt and calls `AIGenerator.generate_response()`, passing the `search_course_content` tool definition
3. DeepSeek decides whether to invoke the tool. If it does, `AIGenerator._handle_tool_execution()` runs the tool via `ToolManager`, sends results back to DeepSeek, and returns the final text
4. `SessionManager` stores the exchange in memory (keyed by session ID, kept to the last N messages)
5. The frontend receives the answer + source list

### ChromaDB collections

- **`course_catalog`** — course-level metadata (title, instructor, link, serialized lessons JSON). Used only for semantic course name resolution (e.g., "MCP" → full course title match).
- **`course_content`** — lesson text chunks with metadata (`course_title`, `lesson_number`, `chunk_index`). This is what gets searched for content queries.

### Document format

Course documents in `docs/` follow a structured plain-text format:

```
Course Title: <title>
Course Link: <url>
Course Instructor: <name>

Lesson 0: Introduction
Lesson Link: <url>
<lesson content...>

Lesson 1: Next Topic
<lesson content...>
```

`DocumentProcessor.process_course_document()` parses this format. Chunking is sentence-aware with configurable overlap (`config.CHUNK_SIZE`, `config.CHUNK_OVERLAP`).

### Frontend

Static HTML/CSS/JS in `frontend/`. `script.js` talks to two endpoints (`POST /api/query`, `GET /api/courses`), renders markdown responses via the `marked` library (loaded from CDN). Session IDs are generated server-side and tracked in the client.

### Key design decisions

- The AI decides **when to search** via OpenAI function calling — the system does not pre-search on every query. The system prompt instructs the AI to search only for course-specific questions.
- Course deduplication on startup: `RAGSystem.add_course_folder()` checks existing course titles before adding, so restarting the server does not re-ingest the same documents.
- Embeddings are generated by `sentence-transformers` (`all-MiniLM-L6-v2`), configured as a ChromaDB embedding function rather than called manually.
- The DeepSeek model defaults to `deepseek-chat` in `config.py`. The API uses LangChain's `ChatOpenAI` with `base_url=https://api.deepseek.com` for OpenAI-compatible access. Temperature is set to `0.01` (DeepSeek rejects `0`).
